# Данные

**Состояние:** проект, кода нет.

Три места, где живут данные: **движок** (узор и работа — в памяти), **телефон** (работы,
наборы, настройки, подписка — в файлах и хранилище) и **сервер студии** (каталог и наборы —
статические файлы, [`03-server-api.md`](03-server-api.md)). Исходники картинок — в
`content/` репозитория ([`09-content.md`](09-content.md)).

## Движок

### Узор

```ts
const CANVAS = 255;                 // клетка канвы: её не вышивают

interface Thread {
  rgb: number;                      // 0xRRGGBB
  name: string;                     // «брусничная»; уникально в пределах узора
}

interface Pattern {
  key: string;                      // «shishkin-utro-v-sosnovom-lesu@1» — картинка и версия узора
  w: number; h: number;             // 1…120 (08-game-design, «Размеры узоров»)
  threads: Thread[];                // 1…32, в порядке полосы нитей: по цвету, от светлых к тёмным
  cells: Uint8Array;                // w × h, построчно: индекс нити 0…31 или CANVAS
}
```

- Номер клетки — `i = y × w + x`. Номер нити в интерфейсе — `индекс + 1`.
- Инварианты (проверяет сборка и загрузка набора): каждая нить встречается хотя бы
  в одной клетке; значения клеток — индексы нитей или `CANVAS`; `w × h ≤ 14 400`.
- Узор с версией (`key`) после выхода не меняется ни на байт (ADR [0010](adr/0010-frozen-patterns.md)).

### Картинка

Запись библиотеки: всё, что показывается вокруг узора. Как её пишут — [`09-content.md`](09-content.md).

```ts
type CollectionId = 'ornaments' | 'painting' | 'tales' | 'russia'
                  | 'flowers' | 'nature' | 'cities' | 'kids';

interface Picture {
  id: string;                       // «shishkin-utro-v-sosnovom-lesu» — вечный, латиницей
  v: number;                        // текущая версия узора; ключ узора — `${id}@${v}`
  title: string;                    // «Утро в сосновом лесу»
  collection: CollectionId;
  order: number;                    // место в коллекции; первые пять (order < 5) бесплатны
  size: 'S' | 'M' | 'L';            // малая, средняя, большая — выводится из числа клеток
  free?: true;                      // бесплатна всегда, независимо от order («Детям»)
  author?: { name: string; life?: string };   // «Иван Шишкин», «1832–1898»
  made?: string;                    // «1889»
  place?: string;                   // «Государственная Третьяковская галерея»
  about?: string;                   // рассказ о картине, 2–4 фразы
  source: { url: string; basis: string };     // откуда исходник и почему можно
  added: string;                    // дата выхода в библиотеку, «2026-10-12»
  hidden?: true;                    // убрана из библиотеки и календаря, узор грузится для работ
}

interface CalendarDay { date: string; picture: string }   // «2026-10-05» → id картинки
```

Карточка YAML в `content/` ([`09-content.md`](09-content.md), §3) — это `Picture` плюс
то, что нужно только сборке: исходник, где хранится оригинал и на каком праве (`museum`,
`license`), параметры узора (`pattern`), рисунок (`drawn`), источники рассказа
(`about_sources`), «да» владельца (`approved`). В набор попадают только поля `Picture`
и палитра.

### Работа

```ts
interface Stroke {                  // один жест: касание, проход кистью или заливка
  thread: number;                   // индекс нити
  cells: number[];                  // клетки в порядке, в каком легли стежки
}

interface Work {
  id: string;                       // «w-<время начала в base36>-<4 случайных знака>»
  pattern: string;                  // ключ узора с версией: работа всегда на своей версии
  strokes: Stroke[];
  started: number;                  // мс
  finished?: number;                // мс, когда лёг последний стежок
}
```

Движок принимает стежок, только если клетка принадлежит этой нити и ещё не вышита;
всё остальное молча отбрасывается. Поэтому `stitched(work)` — вышитые клетки — и процент
всегда выводятся из списка, а «Как вышивалось» — это повтор `strokes` по порядку
(ADR [0005](adr/0005-work-as-stitch-list.md)).

### Что доступно игроку

Одна чистая функция, её проверяют тесты:

```ts
type Access = 'free' | 'daily' | 'started' | 'plus' | 'locked';

function access(p: Picture, ctx: {
  today: string;                    // дата телефона, «2026-10-05»
  seen: string;                     // самая поздняя дата, какую видел телефон: часы назад ничего не запирают
  installed: string;                // дата первого запуска — начало календаря игрока
  dailyFrom: (id: string) => string | undefined;   // когда картинка была картинкой дня
  plus: boolean;                    // действует ли подписка
  hasWork: (id: string) => boolean; // есть ли работа по этой картинке
}): Access
```

По порядку: `free` (`p.free` или `p.order < 5`), `daily` (была картинкой дня между днём
первого запуска и `seen`), `started` (есть работа — дошить можно всегда), `plus` (есть
подписка), иначе `locked`. `seen` хранится на телефоне и только растёт. Правила — [`08-game-design.md`](08-game-design.md), «„Узоры+“ глазами игрока».

## Телефон

Все файлы — в папке приложения (`Paths.document` в `expo-file-system`).

| Путь | Что | Размер |
|---|---|---|
| `works/index.json` | список работ без стежков: id, картинка, даты, сколько вышито, минуты | ~200 байт на работу |
| `works/<id>.log` | стежки работы (формат ниже); рядом `<id>.log.bak` — прошлая копия | 1–25 КБ |
| `packs/<id>.pack` | скачанные наборы (встроенный лежит в APK) | 50–500 КБ |
| `library.json` | собранный указатель библиотеки: картинки, в каком наборе, календарь | 100–300 КБ |
| `previews/<ключ узора>.png` | превью, нарисованные при первом показе; кэш, можно стереть | 1–5 КБ |
| хранилище (`storage.ts`, как в «Вотчине») | настройки, дата установки, подписка, счётчики суток | килобайты |

### Файл стежков

Двоичный, все числа — varint (как в protobuf):

```
"UZW1"                              метка и версия формата
длина и ключ узора (UTF-8)          «shishkin-utro-v-sosnovom-lesu@1»
started                             мс
далее штрихи подряд:
  thread, n, первая клетка, n − 1 разностей в «зигзаге»
```

Разность соседних клеток в штрихе кистью мала (сосед — ±1 или ±w), поэтому клетка
занимает в среднем 1–2 байта: законченная большая работа (14 400 клеток) — около 25 КБ.
Файл переписывается целиком через временный файл и переименование, не чаще раза
в секунду во время кисти и сразу при уходе с экрана или сворачивании приложения;
перед записью прошлая версия становится `.bak`. Испорченный файл (не разобрался, клетка
вне узора) заменяется копией `.bak`; не разобралась и она — работа помечается
повреждённой, а в журнал сбоев уходит запись.

### Наборы и библиотека

При запуске игра разбирает встроенный набор (из APK) и скачанные из `packs/` и
собирает `library.json`, если наборы изменились. Узоры в памяти не держатся все:
для библиотеки хватает карточек и превью, узор разбирается при открытии работы.
Картинка, попавшая в библиотеку, остаётся в ней навсегда (ADR [0010](adr/0010-frozen-patterns.md)):
у исправленной версии узора старая остаётся доступной для начатых по ней работ.

### Подписка

```ts
interface PlusState {
  status: 'none' | 'active' | 'grace' | 'hold' | 'closed';   // как сообщил RuStore Pay
  until?: number;                   // конец оплаченного срока, мс, если RuStore Pay его сообщил
  product?: 'month' | 'year';
  checkedAt: number;                // когда спрашивали RuStore Pay
}
```

Библиотека открыта при `active` и `grace` (льготный период после неудачного списания);
при `hold`, `closed` и `none` — нет ([`10-money.md`](10-money.md), «RuStore»). Правило без
сети: последний ответ действует до `until`; если срок неизвестен — трое суток
с `checkedAt`. Подробно — [спецификация подписки](specs/2026-09-plus.md).

### Счётчики суток

Для запроса каталога ([`03-server-api.md`](03-server-api.md), «Счётчики») телефон копит
за каждый день игры: сколько картинок закончено и сколько минут вышивали (минута
засчитывается, если в ней был хотя бы один стежок). В первый запуск нового дня итоги
прошлого дня игры уходят с запросом каталога и обнуляются. Ничего больше не копится.

### Резервная копия и перенос

- **Автобэкап Android** включён (`allowBackup="true"`, у «Вотчины» наоборот: там в хранилище
  лежит ключ профиля, здесь секретов нет). В копию входят `works/` и настройки; наборы и
  превью — нет: наборы снова скачаются по каталогу, превью нарисуются.
- **«Сохранить работы в файл»** — один файл `uzory-<дата>.uzw` (JSON: формат, дата, работы
  с `index` и стежками в base64) через «Поделиться»; **«Загрузить из файла»** — через
  выбор файла. Работы из файла добавляются к имеющимся; совпавшие по `id` не дублируются.
- Подписка не переносится файлом: она восстанавливается из RuStore — «Восстановить покупки».

## Сервер студии

Только статические файлы и суммы счётчиков. Формат каталога — [`03-server-api.md`](03-server-api.md).

### Набор

Один файл, все числа — little-endian:

```
"UZP1"                              4 байта — метка и версия формата
u32 L                               длина JSON
JSON (UTF-8, L байт)                { id, created, pictures: [карточка + palette: [["#b3162f", "кумачовая"], …]
                                      + at: смещение узора в файле], calendar?: CalendarDay[] }
узоры подряд, в порядке pictures:
  u8 w, u8 h                        размеры
  w × h байт                        клетки построчно: индекс нити или 255 — канва
```

Смещение `at` у каждой картинки позволяет прочитать один узор, не читая набор целиком
(`FileHandle` в `expo-file-system`). Если прототип П4 покажет, что разбор встроенного
набора при запуске или открытие узора медленнее бюджета, встроенный набор становится
готовой базой SQLite (`expo-sqlite` открывает её из APK), а формат `.pack` остаётся
для скачивания.

Палитры лежат в JSON рядом с карточкой: так набор читается одним разбором JSON и одним
проходом по двоичной части. Своего сжатия в наборе нет: у живописи соседние клетки часто
разные, и кодирование сериями почти не выигрывает, а APK сжат сам, и сервер отдаёт наборы
со сжатием gzip.

Набор 1.0 из ~300 картинок — около 2 МБ (оценка по средней картинке 5 000–6 000 клеток),
в APK и при скачивании — примерно вдвое меньше; бюджет встроенного набора — 8 МБ
([`02-architecture.md`](02-architecture.md)).

### Счётчики на сервере

Журнал запросов каталога без адресов раз в сутки сворачивается в таблицу CSV:

```
date, v, s, c, d, p, f, m, count
2026-10-12, 1.0.0, rustore, 2026-10-05, 7, 0, 1, 3, 48
```

Сырые строки журнала живут не дольше семи дней. Сумма и есть всё, что знает студия
об игроках. Как из неё считают удержание — [`05-process.md`](05-process.md), «Счётчики».

## Сроки хранения

| Что | Где | Сколько |
|---|---|---|
| работы, настройки | телефон | пока игрок их не удалит или не удалит игру |
| журнал запросов каталога без адресов | сервер студии | 7 дней |
| суммы счётчиков | сервер студии и копия у владельца | бессрочно: в них нет данных о людях |
| письма «Сообщить об ошибке» | почта студии | год, затем удаляются |

# Как проверяется

**Состояние:** проект. Проверки идут по возрастанию цены: сначала то, что занимает секунды.
Ничего не считается сделанным, пока не пройдены проверки своего уровня.

## 1. Типы и линтер

```bash
npx tsc --noEmit -p .        # приложение
npx tsc --noEmit -p tools    # тесты и сборка картинок (Bun)
npm run lint                 # ни ошибок, ни предупреждений
```

Перед каждым push — у ассистента; в CI — на каждый PR (`pr.yml`, обязательная проверка) и на тег
версии (`android.yml`, вместе со сборкой APK) — [`05-process.md`](05-process.md), «Ветки».
Линтер держит границы слоёв, как у «Анамнеза»: `src/engine/` не импортирует ничего из React,
Expo и `src/state/`; в движке нет `Date.now()` и `Math.random()`.

## 2. Движок

```bash
bun test tools/test
```

- **Стежки.** Стежок чужой нити, вне узора, в клетку канвы и повторный — отбрасываются;
  прогресс равен числу уникальных принятых клеток; порядок в `strokes` сохраняется. Время на
  «Готово» — минуты со стежками: минута, в которую легли стежки, считается раз, перерыв в сутки —
  ни разу (`tools/test/engine.test.ts`); строка «116 640 стежков · 8 часов» — со склонением
  и разрядами, у работы без минут — без времени (`tools/test/i18n.test.ts`).
- **Переигрывание.** Случайные работы (зерно, десять тысяч штрихов на узорах всех
  размеров): запись → файл → разбор → те же вышитые клетки и тот же порядок; повтор для
  «Как вышивалось» проходит все стежки ровно по одному разу.
- **Заливка** — на узорах с известными областями: заливается ровно связная область
  (соседи по сторонам), диагональ не переходит, клетки канвы — граница; вышитые клетки
  область не разрывают, и заливка с уже вышитой клетки заливает остальное.
- **«Где ещё?»** — всегда указывает на невышитую клетку выбранной нити; на законченной
  нити — на следующую нить; на законченной картинке — ничего.
- **Доступность** (`access`) — таблица случаев из [`08-game-design.md`](08-game-design.md),
  «„Узоры+“ глазами игрока»: бесплатная, первые пять каждой коллекции, «Детям», картинка дня
  (сегодня, вчера, завтра, до первого запуска, после перевода часов назад), начатая без
  подписки, подписка кончилась, подписка без сети после срока, льготный период.
- **Календарь** — на каждый день ровно одна картинка; картинка дня не бывает большой;
  картинка не повторяется в календаре; за концом календаря картинка дня выбирается из
  ещё не бывших малых и средних одинаково на любом телефоне с тем же набором.
- **Файлы.** Испорченный файл стежков откатывается к `.bak`; обрезанный на середине
  штриха теряет только этот штрих. Файл, который растёт вместе с работой (`WorkLog`), на каждой
  записи — те же байты, что собранный целиком, и для новой работы, и для открытой из файла; части
  долгого штриха — один штрих, а часть без принятых стежков не продолжает уже записанный
  (`tools/test/files.test.ts`). UTF-8: свой код пишет те же байты, что встроенный и `Buffer`, и
  так же строго отвергает неверные; встроенное чтение, которое неверное заменяет «�» или съедает
  BOM, не берётся. Встроенный набор по частям (`lazyBase64`) — те же JSON и узоры,
  что у декодированного целиком, а байты узора до его открытия не декодируются. Файл «Сохранить
  работы в файл» из прошлой версии
  формата загружается (образцы — в `tools/test/fixtures/works/`, пополняются при каждой
  смене формата).
- **Раздача** (`tools/test/net.test.ts`): собранный каталог разбирается; чужой формат, битый
  id, путь или SHA-256, дубль набора — ошибка целиком; версии сравниваются числами; качаются
  только новые наборы; подпись сходится с нынешним и следующим ключом, чужой ключ и правка
  байта — нет; ключ сценария на телефоне не действует; библиотека из нескольких наборов —
  последняя версия в списке, прежняя для работ, та же версия не дублируется, календарь
  позднего набора правит день.
- **Счётчики** (`tools/test/counters.test.ts`): корзины дней, картинок и минут как в таблице
  [`03-server-api.md`](03-server-api.md); минута со стежком — один раз; первый запрос нового
  дня несёт итоги прошлого дня игры, повтор — без счётчиков; «60+» в адресе закодирован;
  неотданный день теряется; свёртка журнала — только полные строки с кодом 200/304 и известными
  значениями, законченные дни один раз, строки старше семи дней удаляются.
- **Перенос** (`tools/test/backup.test.ts`): туда и обратно без потерь; не файл «Узоров» и
  другая версия — ошибка целиком; id, из которых вышли бы чужие имена файлов (`../`, `/`,
  заглавные), отбрасываются; испорченная работа или узор пропускаются, остальное на месте;
  лишние поля записи в указатель не попадают; совпавшая по id работа заменяется, только если
  в файле вышито больше; работа своего узора — только вместе с узором; минуты со стежками
  переносятся, если это целое не меньше нуля, а иное отбрасывается само, без работы.
- **Запуски и сбои** (`tools/test/sessions.test.ts`, 0.14.0): первый запуск — счёт с сегодня,
  идущая сессия не в счёте; ушла в фон и вернулась — сессия закончилась как положено; не ушла в
  фон до следующего запуска — оборвалась; испорченная запись — счёт с сегодня; в отчёте об ошибке —
  строки запусков и законченных картинок перед журналом, «счёт не прочитался», если не прочитался.
- **Итоги закрытого теста** (`tools/test/reports.test.ts`): отчёт, который пишет игра, разбирается
  обратно теми же подписями (`tools/reports/tally.ts`) — во всех двенадцати месяцах; из нескольких
  отчётов одного человека берётся тот, где запусков больше; суммы сверяются с воротами 1.0, доля без
  сбоев — с округлением вниз: 99,46 % — не «99,5 %».
- **Подписка** (`tools/test/plus.test.ts`, 0.12.0): «действует» и льготный период открывают
  библиотеку до конца оплаченного срока, без срока — трое суток с проверки; приостановка,
  закрытая и не бывшая — нет; испорченная запись — как «подписки не было»; строка «Узоры+» на
  «Готово» — не в первые три дня, не второй раз за день и только после бесплатной картинки; день
  следующего списания — через месяц или год, 31 января → последний день февраля.

## 3. Картинки

```bash
bun tools/content/build.ts --check    # то же, что в CI
```

Для **каждой** картинки ([`09-content.md`](09-content.md), «Проверки»):

- карточка по схеме: название, коллекция, источник и основание, у живописи — автор,
  годы жизни, год картины; автор проходит правило срока ([`09-content.md`](09-content.md),
  «Права»);
- узор в пределах размера; нитей в пределах размера; у каждой нити не меньше заданного
  числа клеток; любые две нити различимы (порог расстояния в OKLab);
- одиночных клеток («конфетти») не больше порога; ни одной нити, все клетки которой —
  одиночки;
- названия нитей уникальны в узоре; превью собирается;
- идентификатор уникален и латиницей.

**Бесплатные картинки** (`tools/test/content.test.ts`): в каждой коллекции выпуска без подписки
открыты первые пять (`order` 0–4, их выбирает владелец), а если картинок меньше — все. Тест берёт
карточки с «да» и правило `access` игры, узоры для него не собираются.

**Рассказ о картине** (`tools/test/content.test.ts`, `fixtures/bad-cards/`): у каждой картинки
выпуска из «Живописи», «Сказок» и «России в цвете» есть рассказ; у рассказа — два разных адреса
источников, и он не длиннее 400 знаков ([`09-content.md`](09-content.md), §7).

**Обещания — по выпуску** (`tools/test/store.test.ts`): тексты RuStore и сайта, частые вопросы,
памятка тестировщику и надписи баннера не называют коллекцию, в которой нет ни одной картинки
с «да» владельца и правами, и музыку, пока ни у одной пьесы нет «да» (В6) — «ни одного обещания,
которого нет в игре» ([`specs/2026-09-v1.md`](specs/2026-09-v1.md), «Карточка RuStore»). Тест
берёт карточки и список пьес, ничего не собирая. С 15.10.2026 у всех пяти пьес «да» (0.15.0), и
музыка в текстах снова названа.

Календарь встроенного набора (`tools/test/calendar.test.ts`): коллекции вперемешку, две
одной подряд — только когда больше нечего; картинка со временем года — только в свой сезон
и вразбивку по нему; праздник (`day`) — ровно в свой день; тот же набор — тот же календарь.
Календарь набора недели (0.13.0): не дальше заданных дней, первый день — не коллекция
вчерашнего, день из `pin` — ровно в свою дату и важнее праздника карточки.

**Испорченный узор** (`tools/test/checks.test.ts`): чистый узор проходит и у «Детям»; одна
одиночная клетка — ошибка у «Детям», но не у картины; нить из одних одиночек, неразличимые нити,
нить меньше восьми клеток, мелкие пятна больше 3 % — ошибки. Образцы-карточки
(`fixtures/bad-cards/`) ловят схему карточки, этот тест — сам узор.

**Набор недели** (`tools/test/week.test.ts`, 0.13.0): неделя по ISO и `content/week.yaml`; в
набор — только новые картинки и новые версии, видны с `from`; календарь продолжает выпущенный
без разрыва и без той же коллекции на стыке, бывшие картинкой дня не повторяются, `pin` вне
недели — ошибка; каталог — выпущенные наборы как были, новый в конце, подпись сходится; уже
выпущенный `id`, «нечего выпускать» и набор без первого каталога — ошибка; выпущенное с сервера
читается с проверкой подписи, размера и SHA-256.

**Золотой тест выпущенного.** `tools/test/fixtures/released.json` — ключ каждого
выпущенного узора и SHA-256 его клеток и палитры. Тест падает, если выпущенный узор
изменился или исчез (ADR [0010](adr/0010-frozen-patterns.md)). Второй тест падает, если узор
картинки с «да» не закреплён: с «да» он уходит в APK по тегу версии.

С 4.10.2026 в списке 296 узоров — весь встроенный набор APK `v0.14.3`; в нём и 240 узоров `v0.14.2`,
с которым начат закрытый тест. Наборы, вынутые из самих APK, совпали до байта со сборками тех же
коммитов у ассистента: `v0.14.2` — SHA-256 `e20f6cab…`, `v0.14.3` — `5aa8a3e8…`. С 14.10.2026 в списке
313 узоров: добавились 17 снимков «России в цвете» с «да» (0.14.5). С 15.10.2026 — 376: и новые версии
63 своих снимков (`@2`, 0.14.7); прежние (`@1`) остались и в списке, и в наборе — скрытыми, для начатых работ.
С 0.15.1 — 387: четыре старинные схемы без белых точек (`@2`) и семь снимков с глазами (`@3`); прежние — так же.

Список пополняют `bun tools/content/week.ts --base --freeze` в PR с «да» и `--freeze` в PR набора
недели; записанное они не меняют. При каждой выкладке `content.yml` сверяет то же с наборами на
сервере ([`05-process.md`](05-process.md), «Выкладывание наборов»).

**Детерминированность сборки.** Сборка дважды подряд даёт одинаковые наборы до байта. На двух
машинах сверено 3.10.2026: сборка main `a47fd2a` на раннере CI и у ассистента — один SHA-256 набора
(`911c2a73…`). С 4.10.2026 это держит золотой тест выпущенного: CI на каждом PR сверяет 387 узоров с
отпечатками, записанными у ассистента (`--freeze`).

**Время сборки** (`tools/test/content.test.ts`): картинка — до 2 с, огромная — до 10 с; что дольше,
отчёт сборки показывает разделом «Дольше предела» — предупреждением, не ошибкой: время зависит от
машины. В заголовке отчёта — сколько секунд ушло на все узоры. В CI 3.10.2026 самая долгая не огромная
картинка (старинная схема) — 1,1 с, огромная — 2,8 с, весь набор из 194 картинок — меньше двух минут.

**Свой узор** (`tools/test/mine.test.ts`, [спецификация](specs/2026-09-custom.md)): карточка,
скачанная из инструмента, несёт все поля сетки — кадр, размер, упрощение, `grid: dominant` и
`chroma: 1.15`, — и сетка по ней (`photoGrid`, та же, что в `tools/content/build.ts`) даёт тот же
узор до байта; цвет клетки — преобладающий: полосы красного и зелёного по полторы клетки дают две
нити того же оттенка, только ярче, а среднее по площади смешало бы третью, бурую; приговор —
«не подходит» у шахматки, «подходит, но» у тёмного, мелкого и одноцветного снимка, а по готовым
числам проверок — каждая строка таблицы спецификации на самих границах (одиночных 1 % и 0,8 %,
мелких пятен 3 % и 2,4 %, две точки снимка на клетку, две нити) и у каждой беды — свой совет;
карточка для библиотеки проходит проверку карточек, и упрощение в ней — тоже. В сценарии
Playwright — снимок, рамка колёсиком, размер; «Зонтики в парке» без упрощения подходят (по
преобладающему цвету лес не рассыпается, 0.15.0); пёстрая листва, которую рисует сам сценарий, без
упрощения — «не подходит» и «Вышивать» неактивна, с «сильно» — подходит; в карточке — `grid: dominant`
и `chroma: 1.15`; «Вышивать», продолжение после перезагрузки; от
выбора снимка до перезагрузки страница не делает ни одного запроса, кроме чтения файлов
самой сборки.

**Звуки** (`tools/test/audio.test.ts`): каждый файл `assets/audio` — WAV моно 16 бит 22 050 Гц без
перегрузки, со строкой в `LICENSES.md`; файлы совпадают с тем, что пишет `tools/audio/gen.ts`, до
байта; стежок короче 0,1 с; игра подключает все файлы. Как звучат, слушает человек на телефоне.

**Музыка** (`tools/test/music.test.ts`): у каждой пьесы `assets/music/music.yaml` — лицензия
записи, которую можно выпускать (общественное достояние, CC0, CC BY; `NC`, `ND`, `SA` —
ошибка сборки), и страница Викисклада, где это сказано; файл — WebM с Opus, моно; вся музыка —
не больше 10 МБ; в сборку выпуска попадают только пьесы с «да». Круг — все пьесы по разу, без
повтора на стыке кругов; нарастание — от тишины, первые секунды почти тихо. Запускают музыку
только на экране вышивания. В сценарии Playwright страница записывает, что просили у её
проигрывателей: без стежка музыка не звучит; первый стежок — пьеса с нулевой громкостью за
пять секунд доходит до половины, и браузер её играет; «Музыка» в меню ⋮ — выключили: затихла
и пауза, включили: снова; ушли с экрана — пауза; в настройках — переключатель, в «О программе» —
пьесы с исполнителями и лицензиями. Как звучит на телефоне (громкость рядом со звуками, звонок,
сворачивание), слушает человек.

**Подсказки и игрок** (`tools/test/hints.test.ts`, [спецификация](specs/2026-09-first-picture.md)):
первая картинка по порядку — касание, кисть, два пальца, «Где ещё?»; кто сделал раньше, подсказку
не увидит; подсказка, которую не на чем выполнить, уступает следующей и не возвращается;
испорченная запись игрока приводится в порядок, а `seen` только растёт. В сценарии Playwright —
главная с первой картинкой, «Скоро» у библиотеки, настройки запоминаются, «О программе», меню ⋮
со стилем, подсказки «щёлкните клетку» → «проведите мышью» → «Где ещё?», после первой картинки
на главной — картинка дня.

**Упрощение** (`tools/test/simplify.test.ts`, `mine.test.ts`): «нет» — сетка и узор те же, что
без настройки; граница двух пятен с шумом остаётся на месте, а шум внутри уходит; бумага
схемы не трогается и в соседей не подмешивается; шашечку чистка по одной сливает, а чистка
«все сразу» только меняет цветами; пёстрая листва без упрощения рассыпается на мелкие
пятна, с ним — ни одиночек, ни мелких пятен, и узор тот же, что соберёт `tools/content` по
карточке с `pattern.simplify`.

**Преобладающий цвет и насыщенность** (`tools/test/dominant.test.ts`, 15.10.2026): клетка, где красного
70 %, а синего 30 %, выходит красной, а среднее по площади — лиловой смесью; ровная клетка — ровно
своим цветом, поровну — тёмной половиной; клетки и размеры — как у среднего, две сборки подряд
одинаковы. Насыщенность ×1,15 поднимает хрому ровно в 1,15 раза при той же светлоте и оттенке,
серое остаётся серым, вышедшее за sRGB обрезается. Прежние версии узоров (`was` в карточке) —
`tools/test/content.test.ts`: в наборе они скрытые и после всех картинок, библиотека и поиск по
`id` находят нынешнюю версию, календарь — только нынешние; золотой тест сверяет и их.

**Старинные схемы по скану** (`tools/test/chart.test.ts`, [спецификация](specs/2026-09-schemes.md)):
схема 40 × 30, нарисованная с подвохами настоящих сканов — бумага растянута, каждая десятая
линия толще, шов склейки со сдвигом сетки, поле без сетки и рамка. Сборка находит ровно
40 × 30 клеток, цвет каждой — её краска или бумага (у шва — единицы неточных), краска
никогда не становится фоном, а пожелтевший белый лист после выбеливания даёт те же краски.
Берлинский лист с прозрачной краской (0.15.1): трава, сквозь которую видна сетка, с образцами
бумаги до 0,2 сходит за бумагу, а с `canvas_seed: 0.1` — ни одной клетки; белила цвета бумаги
посреди травы с `canvas_holes: 6` — краска, а поляна в 20 клеток и выемка у края травы — фон.
Испорченная карточка: `canvas_seed` и `canvas_holes` у картины, без бумаги схемы, — ошибка.

**Глаза снимка** (`tools/test/eyes.test.ts`, 0.15.1): на снимке с рыжей мордой глаз радиусом
2,5 точки при клетке в 6 — без рамок уходит в шерсть; по рамке — клетка глаза тёмной нитью узора,
новых нитей нет, остальные клетки те же; светлый глаз на тёмном — светлой нитью; рамка без глаза —
ничего, рамка мельче клетки — клетка под её серединой; та же рамка — те же глаза. Испорченная
карточка: `eyes` у старинной схемы — ошибка.

**Глазами.** Лист превью, приложенный к PR, смотрит владелец ([`05-process.md`](05-process.md),
«Второй поток: картинки»). Автоматика ловит сломанное, но «красиво ли» решает человек.

## 4. Канва

- **Шейдер** (`tools/test/shader.test.ts`): CanvasKit без видеокарты (`bun test`) рисует
  узор-образец далеко и близко, «Крестиком» и «Мозаикой»: цвет в центре каждой вышитой клетки —
  цвет нити. Так ловятся ошибки шейдера, которые иначе видны только на телефоне. Задумано, но
  пока не сделано: сверка кадра целиком с эталоном и кадры с выбранной нитью. С 0.14.6 тест
  проверяет и то, что крестик на мелкой клетке не бледнит нить. Берётся клетка 22 точки, как на
  картинке «Поделиться» узора в 70 клеток, и пять нитей: красная, тёмно- и светло-зелёная,
  голубая, розовая. Средний цвет клетки должен сохранить не меньше трёх четвертей насыщенности
  нити, а светлота — уйти не больше чем на 0,07. Прежний крестик оставлял 29–58 % насыщенности,
  тёмно-зелёная нить светлела с 0,38 до 0,61. На клетке от 44 точек крестик прежний: у середины
  стороны — канва, в середине — нить.
- **Контраст номера** (`tools/test/contrast.test.ts`, 0.14.1): правило шейдера, по которому
  номер на клетке тёмный, чёрный или белый, повторено на процессоре с числами из самого
  шейдера; на каждой нити встроенного набора и на выборке всего куба цветов (свой узор бывает
  любым), на полотне и плитке, с подсветкой и в полоске штриховки — не ниже 4,5 : 1
  ([`08-game-design.md`](08-game-design.md), «Для старшей аудитории»).
- **Размер номера** (`tools/test/canvas.test.ts`): кегль номера — шрифт атласа цифр, его ячейка
  (`src/canvas/glyphs.ts`) и доля клетки под цифру из самого шейдера. На самой мелкой клетке,
  где номера ещё видны (18 dp), он не меньше 13 sp: сейчас 13,1. «Крупные номера» — клетка 36 dp.
- Кисть между замерами пальца проходит все клетки, которые пересекает отрезок
  (Amanatides–Woo), — сверка с перебором на случайных отрезках (`tools/test/canvas.test.ts`).
- Камера: масштаб не выходит за пределы, канву не увести за край, малая картинка открывается
  целиком, масштаб — вокруг точки под курсором. Задумано: перевод касания в клетку на границах
  клеток и «Где ещё?» ставит клетку в видимую часть.
- **Замер на телефоне** (скрытый экран «Замер», как в «Вотчине»: семь касаний по версии
  в настройках): узор 150 × 200 и узор 120 × 120, пан, масштаб и кисть по 30 секунд —
  кадров в секунду, худший кадр, задержка «палец → стежок», память. Пороги —
  [спецификация прототипов](specs/2026-09-spikes.md), числа — в [`02-architecture.md`](02-architecture.md).

## 5. Сквозные сценарии

Веб-сборка + Playwright (Chromium уже стоит в среде). CanvasKit грузится раньше модулей
Skia, как у «Анамнеза». Узор в тестах — маленький, стежки ставятся касаниями по
координатам клеток.

Сейчас (0.5.0) это `tools/e2e/smoke.ts`: главная, настройки и «О программе», первая
картинка от первого стежка до «Готово» и «Как вышивалось» (касание, чужая клетка, заливка,
кисть, меню ⋮, подсказки; на «Готово» — стежки и минуты со стежками, хотя между заходами сценарий
слушал музыку и открывал лист), «Поделиться» — скачанный PNG разбирается по той раскладке, по
которой его рисует приложение (`src/engine/share.ts`, `tools/e2e/share.ts`): размер, фон, рамка,
паспарту, строки подписи; одна и та же своя работа студии (клетка 64 точки) со «Стежками на
картинке» в «Крестике» — крестиками (у середины стороны клетки — не нить, в середине — нить), в
«Мозаике» — плиткой, а без них (так сразу после установки, 0.15.0) — ровным цветом; подписи картины у
неё нет; в настройках «Стежки на картинке „Поделиться“» сразу выключены и запоминаются; после «Поделиться» — картинка дня на главной, библиотека → «Все» → карточка →
«Вышивать», «Мои работы» с удалением долгим касанием,
календарь (библиотека при замедлении процессора в четыре раза отвечает на «назад» быстрее двух
секунд, 0.10.3), орнамент из библиотеки до «Готово» и «Дальше» — карточка картинки дня; «Лист»
открывается быстрее полутора секунд (превью — при показе карточки, 0.10.1); отбор в
«Листе» — «Да», «Нет», снятая отметка, «Скопировать решения» (текст в буфере обмена), фильтр
«Без отметки», коллекция отдельно (0.10.2); образец экрана «Узоры+» — цены, автопродление, где отменить, неактивная покупка, «Восстановить покупки», а «Как в 1.0» запирает картинку «Узоры+» и снимается (0.12.0); «Готово» большой
картины (работа без последней клетки подкладывается в хранилище отдельной вкладки,
`tools/e2e/seed.ts`) — «Как вышивалось» от 8 до 12 секунд и в конце все стежки, «О картине» с автором и
источником, «Поделиться» (клетка мелкая — цветом, три строки подписи), «Дальше»; «Сообщить об
ошибке» — запуски, оборвавшиеся и законченные картинки (0.14.0); пипетка долгим касанием и смена
стиля посреди работы — канва перерисована, работа, нить и приближенная камера на месте; свой узор
вышивается, после перезагрузки и переноса файлом — тот же процент; без сети с чистой установки
(сервер картинок не отвечает) — до первого стежка два касания, главная без строки о сети, картинка
дня из календаря и большая картинка «России в цвете» из библиотеки открываются и вышиваются, на их
карточках — «Продолжить», в консоли — только отказы сети; «далеко» на большой картинке — щелчок не
вышивает, а приближает это место до масштаба открытия, перетаскивание двигает канву без единого
стежка, «Где ещё?» со всего узора летит к ближайшей группе нити (по `nearestGroup`) и приближает —
щелчок по её клетке вышивает; пальцы — касания через CDP (`Input.dispatchTouchEvent`): касание вышивает клетку, второй
палец в первые 100 мс снимает стежок и канва остаётся как была, второй палец позже — стежок
остаётся; подсказка про колёсико — на середине первой картинки, если камеру ещё не трогали (в
чистой вкладке), и уходит после колёсика; «Перенос» —
«Сохранить работы в файл», «Загрузить из файла» в чистой вкладке (работы, свой узор и картинка дня
на главной на месте), тот же файл второй раз ничего не добавляет; раздача картинок с поддельного
сервера — каталог с чужой подписью не тронут, новый набор с меткой «Новое», набор с неверным
SHA-256 не появляется, строка запроса каталога — ровно параметры счётчиков из таблицы, каталог
раз в сутки, строка «обновите» при `minApp` выше версии; мышь,
клавиши и мини-карта (колёсико
приближает к курсору, правая кнопка двигает, «+» и «0» — щелчок после каждого действия
попадает в рассчитанную клетку), начатая картинка из «Листа» открывается с тем же процентом,
лист, файл работы, замер (три фазы, коммитов React во время кисти — 0); «убить посреди кисти» —
вкладка падает посреди штриха (`Page.crash`), новая открывает работу: за штрих она записывалась
каждую секунду, пропал только конец следа, не больше 1,25 с; «Узоры+» с заглушкой RuStore Pay
(`src/state/fakeBilling.ts`, только в сборке 0.x на 127.0.0.1): цены магазина, отказ — тихо, сбой —
строка, покупка — и назад на карточку уже с «Вышивать», «нет RuStore»; строка «Узоры+» на «Готово» — на
третий день после бесплатной картинки, второй раз за день и в первые три дня — нет, на главной — нет;
календарь с подменённой датой (часы браузера — `page.clock`, сети нет, «Как в 1.0»): вчерашняя картинка
дня открыта, завтрашней в календаре нет и в коллекции она заперта, назавтра — открыта, а часы,
переведённые назад, её снова не запирают. Сборка отдаётся с правилами
безопасности (CSP) папки игры
на сайте — несовместимое падает ошибкой в консоли. Прогонов два: от корня (`npm run e2e`)
и из папки сайта (`E2E_DIST=dist-site E2E_BASE=/uzory/test`,
[спецификация веб-версии](specs/2026-09-web.md)); в CI первый идёт в сборке APK на теге, второй —
в `site.yml` перед выкладкой на сайт. Цель 1.0 — список ниже.

- Первая картинка от запуска до «Готово» и главного экрана с картинкой дня.
- Библиотека: бесплатная картинка открывается, «Узоры+» — ведёт на экран подписки
  (RuStore Pay в вебе — заглушка с режимами «куплено», «отказ», «нет RuStore»; с 15.10.2026 —
  `src/state/fakeBilling.ts`).
- Работа переживает перезагрузку страницы посреди кисти — с 15.10.2026 сценарий роняет вкладку
  посреди штриха (`Page.crash`).
- Календарь с подменённой датой: вчерашняя картинка дня доступна, завтрашней нет — с 15.10.2026 в
  сценарии (`page.clock`).
- Каталог и набор с поддельного сервера: новый набор появляется; набор с неверным
  SHA-256 не появляется и библиотеку не трогает; каталог с неверной подписью
  игнорируется целиком.

## 6. Телефон

Перед выпуском, на опорном телефоне (самом недорогом) и на одном современном
([`07-roadmap.md`](07-roadmap.md), вопрос об опорном телефоне). Пороги — из спецификаций; ниже —
что открыть и где взять число, один заход примерно на час. Числа присылаются ассистенту
сообщением: в «Замере канвы» и «Файле работы» есть кнопка «Поделиться числами», числа ложатся в
[`02-architecture.md`](02-architecture.md) и «Что изменилось» спецификаций.

**Перед заходом.** APK последнего тега из Releases ставится поверх прежней версии и открывается
([прототипы](specs/2026-09-spikes.md), критерий 1). Телефон заряжен, энергосбережение выключено.

1. **Холодный запуск** — до главного экрана не дольше 3 с на опорном
   ([первая картинка](specs/2026-09-first-picture.md), критерий 4). Остановить игру (настройки
   Android → «Приложения» → «Узоры» → «Остановить»), коснуться иконки и засечь, когда видна
   картинка дня. Три раза, в ответ — худшее.
2. **Канва** — «Для проверки» → «Замер канвы»: «150 × 200 · 40», «Шейдер», TextureView,
   «Крестик», «3 × 30 с», «Запустить замер» — и не трогать экран. Сразу второй прогон: первый
   греет шейдер (кадр в 405 мс был в первом). Пороги на опорном ([прототипы](specs/2026-09-spikes.md),
   критерии 2–4): 95-й процентиль — не больше 25 мс (не больше 20 — пройден и узор 120 × 120);
   «дольше 33 мс» — не больше 5 %; «худший» во втором прогоне — не больше 100 мс; «жест p95» — не
   больше 2 мс, «текстура p95» — не больше 3 мс; «коммитов React» — 0. На современном телефоне
   95-й процентиль — не больше 16,7 мс. Потом то же на «852 × 556 · 30»: порогов нет, нужны числа.
3. **Файл работы** — «Для проверки» → «Файл работы» → «Проверить»
   ([прототипы](specs/2026-09-spikes.md), критерии 7 и 9): «Размер файла» — не больше 40 КБ;
   «Запись на диск» и «852 × 556: запись во время вышивания» — не больше 20 мс; «Чтение, разбор и
   переигрывание» — не больше 300 мс; «Встроенный набор: узор по смещению» — не больше 150 мс.
   «UTF-8» — какой код работает, встроенный или свой; «Указатель на 365 работ: обновление» вместе
   с «852 × 556: запись во время вышивания» — не больше 20 мс: на каждой записи работы
   переписывается и указатель.
4. **Убить посреди кисти** — теряется не больше секунды стежков ([канва](specs/2026-09-canvas.md),
   критерий 4; в веб-версии это проверяет сценарий, §5): открыть большую картинку, вести кистью и, не отпуская палец, смахнуть игру из
   недавних. После нового запуска пропал только конец следа — не больше, чем кисть проводит за
   секунду.
5. **Прокрутка библиотеки** — ни одного кадра дольше 50 мс ([библиотека](specs/2026-09-library.md),
   критерий 4): сразу после запуска — «Библиотека» → «Все» у «Орнаментов», пролистать быстро до
   конца и назад, пока превью ещё не нарисованы. На глаз — без рывков. Точно — с компьютером:
   `adb shell dumpsys gfxinfo games.gornitsa.uzory reset`, прокрутка, затем
   `adb shell dumpsys gfxinfo games.gornitsa.uzory`: в строке «HISTOGRAM» у корзин дольше 50 мс — нули.
6. **Пипетка** — долгое касание клетки выбирает её нить и щёлкает вибрацией
   ([канва](specs/2026-09-canvas.md), критерий 1; «Вибрация» в настройках игры включена).
7. **Крупный шрифт и тёмная тема** — самый крупный шрифт в настройках Android: главная, первая
   картинка с полосой нитей, «Готово», библиотека, карточка картинки, настройки, «Узоры+» —
   ничего не обрезано ([первая картинка](specs/2026-09-first-picture.md), критерий 5). С тёмной
   темой Android — тот же обход.
8. **Без сети** — авиарежим: главная, картинка дня, календарь, библиотека; большая картинка
   открывается и вышивается. С сетью — новый набор, когда выкладка заработает (В9, В18).
9. **Звук и сворачивание** — музыка, звуки и вибрация; звонок посреди вышивания; свернуть и
   вернуться — работа на месте.
10. **Память** — с компьютером ([прототипы](specs/2026-09-spikes.md), критерий 6):
    `adb shell dumpsys meminfo games.gornitsa.uzory`, строка TOTAL — на главной, с открытой большой
    картинкой и после десяти минут кисти: канва добавляет не больше 60 МБ, за десять минут кисти —
    не больше 20 МБ.

Дольше одного захода:

- большая картинка от первого до последнего стежка — ни одного подвисания, файл цел;
- «Сохранить работы в файл» на одном телефоне, «Загрузить из файла» на другом — все работы на
  месте, готовые готовы ([«Узоры+»](specs/2026-09-plus.md), критерий 5);
- автобэкап: работа возвращается после переустановки с восстановлением копии;
- подписка в тестовом режиме RuStore Pay — после В2: покупка, восстановление после
  переустановки, окончание, телефон без RuStore.

## 7. Сборка APK

CI проверяет каждый файл ([`05-process.md`](05-process.md)): подпись постоянным ключом,
белый список разрешений, выравнивание 16 КБ, `allowBackup="true"` и правила копии,
размер APK не больше 90 МБ с двумя архитектурами и встроенный набор не больше 8 МБ
([`02-architecture.md`](02-architecture.md), «Ограничения»).

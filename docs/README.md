# Документация «Узоров»

Здесь лежит всё, что нужно, чтобы вести проект, ничего не помня о нём заранее.
Документация живёт в репозитории рядом с кодом и меняется вместе с ним: правка кода
без правки документа — незакрытая задача. Устройство документов повторяет «Вотчину» —
первую игру студии, которая дошла до магазинов; отличия оговорены там, где они есть.

**Сейчас кода нет.** Документы `02`–`04` и `08`–`09` описывают задуманное устройство.
С первой строки кода они описывают то, что есть, а расхождение с кодом правится в том же коммите.

## Как мы работаем

Как в «Вотчине» — «сначала спецификация, потом код» (SDD — specification-driven development):

1. Спецификация в `specs/`: что должно получиться, экраны, данные, неудачные случаи,
   критерии приёмки.
2. Код и тесты по спецификации.
3. Правка затронутых документов, дорожной карты; ADR, если решение дорого менять.
4. Выпуск по чек-листу из [`05-process.md`](05-process.md).

У «Узоров», как у «Анамнеза», есть второй поток работы — **картинки**. Новые картинки
добавляются не спецификациями, а записями в `content/` по правилам [`09-content.md`](09-content.md);
каждую проверяет сборка, а в выпуск она идёт только после «да» владельца по листу превью.

Мелкие правки (текст, цвет, исправление ошибки) спецификации не требуют — только запись
в разделе версии корневого `README.md`.

## Правила этих документов

- **Русский язык, человеческие формулировки.** Документы читают люди, пишет их часто ассистент.
- **Одно место для факта.** Числа геймдизайна — только в `08`, правила картинок и права
  на них — только в `09`, форматы — только в `04`, раздача — только в `03`, деньги
  и право — только в `10`, рыночные цифры — только в `11`. В остальных местах — ссылка.
- **Задуманное помечено.** Пока кода нет — «проект»; после — задуманное живёт в `specs/`
  и дорожной карте.
- **Гипотезы отделены от фактов.** Цены, бесплатная часть, цели удержания, время на
  картинку — гипотезы и помечены так; факты — со ссылкой на источник и датой.
  Рыночные цифры, взятые из поисковой выдачи без открытия страницы, помечены [в].
- **Комментарии в коде — про «почему».** Документация — про устройство и договорённости.

## Карта репозитория (задуманная)

```
App.tsx                переключатель экранов
src/engine/            узор, стежки, заливка, «Где ещё?», календарь, доступность: чистый TypeScript
src/canvas/            экран вышивания: Skia, камера, жесты, кисть
src/render/            стили стежков, превью, рамки, рушники, картинка для «Поделиться»
src/state/             библиотека и наборы, работы, настройки, подписка, сеть, журнал сбоев
src/screens/           главная, библиотека, календарь, мои работы, карточка, готово, «Узоры+», настройки
src/ui/                общие элементы, тема, диалог
src/i18n/              тексты
content/               исходники картинок: карточки YAML и уменьшенные оригиналы
assets/                встроенный набор, музыка, шрифты, иконка
plugins/               плагины конфигурации Expo: подпись, RuStore Pay, правила резервной копии
server/stats/          свёртка журнала каталога в счётчики (выкладывается на сервер студии)
tools/content/         сборка картинок в наборы, проверки, лист превью
tools/test/            тесты движка, картинок, файлов
tools/e2e/             сценарии Playwright на веб-сборке
tools/store/           снимки для магазина, загрузка в RuStore
docs/                  эта документация
research/              эксперименты технического разбора (не код игры): шейдер канвы, сборка узора
.github/workflows/     сборка APK, сборка и выкладывание наборов, сценарии, загрузка в RuStore
```

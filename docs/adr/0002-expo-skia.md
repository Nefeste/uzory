# 0002. Expo / React Native / TypeScript, как у соседей; канва — Skia

*Общее правило — ADR студии [0003](https://github.com/Nefeste/gornitsa/blob/main/adr/0003-expo-stack-ci.md) в уставе «Горницы» (`Nefeste/gornitsa`). Эта записка остаётся как история решения и описание того, как оно устроено в проекте.*

**Решили.** Приложение — Expo SDK 57 (React Native 0.86, React 19, Hermes, React Compiler,
TypeScript), как «Вотчина», «Нарды» и «Анамнез». Канва рисуется `@shopify/react-native-skia`,
жесты и камера — `react-native-gesture-handler` и `react-native-reanimated` на UI-потоке,
версии — как у «Анамнеза», где эта связка уже на телефоне. Движок, сборка картинок, тесты —
тот же TypeScript под Bun.

Канва рисуется **одним шейдером** `RuntimeEffect` поверх маленьких текстур данных — клеток,
палитры и цифр; запасной путь — «слои»: изображение «клетка = точка» без сглаживания,
сетка одним путём и цифры через `Atlas` только для видимых клеток
([`02-architecture.md`](../02-architecture.md), «Канва»). Прототип П2 меряет оба на опорном
телефоне, и остаётся тот, что держит порог.

**Почему.**

- **Всё, кроме канвы, — обычный интерфейс**: списки, карточки, настройки, подписка. Здесь
  React Native сильнее игровых движков, а путь до магазинов (CI без EAS, подпись, RuStore,
  снимки, тексты, тесты) уже пройден «Вотчиной» и переносится целиком.
- **Канва — не игровой мир, а сетка.** Всё её состояние — изображение 120 × 120 точек,
  и шейдер рисует её за один проход при любом масштабе: цена кадра зависит от экрана,
  а не от узора. Прототип шейдера уже собран на CanvasKit той же версии, что у Skia
  в Expo SDK 57, и возвращает точные цвета клеток. Для сравнения: карта «Анамнеза»
  на Skia (610 спрайтов) — 120 кадров в секунду на телефоне владельца.
- **Один язык** для движка, сборки картинок и тестов: узор, который собрала сборка, читает
  тот же код, что и телефон.
- Ассистент на этом стеке работает надёжнее всего (опыт трёх проектов).

**Платим.**

- Камеру, кисть, заливку и отрисовку канвы пишем сами — в игровом движке часть этого
  была бы готовой. Шейдер на SkSL — отдельное умение, и его ошибки видны только на экране:
  поэтому золотые кадры канвы проверяются в тестах на CanvasKit ([`06-testing.md`](../06-testing.md)).
- В Skia 2.6.2 (версия Expo SDK 57) ошибка выборки без сглаживания: обходим ручной сборкой
  шейдера или переходим на 2.13 — по итогам П2.
- Skia — несколько мегабайт к APK; в вебе — CanvasKit, только для проверок.
- Expo ломает API от версии к версии — правило «читать версионную документацию, а не
  память» в `AGENTS.md`.

**Что отвергнуто.**

- **Godot, Unity, Flutter** — пайплайн «Вотчины» не переносится, движок и сборка картинок
  оказались бы на другом языке, а игрового мира, ради которого берут движок, здесь нет.
- **Отрисовка клеток обычными `View`** — десятки тысяч элементов: подвисает уже на
  средних узорах.

**Когда пересмотреть.** Если прототип П2 не держит свои пороги на опорном телефоне ни одним
из двух путей ([`specs/2026-09-spikes.md`](../specs/2026-09-spikes.md)) — новая ADR: меньший
предельный размер узора или нативный модуль канвы.

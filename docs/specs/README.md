# Спецификации

Здесь лежат описания возможностей — то, что пишется **до** кода и остаётся после как ответ
на вопрос «а как это вообще задумано». Спецификация — договор: если чего-то в ней нет,
это обсуждается до начала работы, а не выясняется в процессе.

Файл называется `ГОД-МЕСЯЦ-краткое-название.md` — по дате начала работы, а не окончания.
Написанная спецификация не переписывается «чтобы совпало с кодом»: если по ходу дела решение
изменилось, правка вносится в раздел «Что изменилось по ходу работы» в конце файла.
Так видно не только результат, но и почему он не такой, как задумывали.

Факты не копируются: числа геймдизайна — в [`../08-game-design.md`](../08-game-design.md),
правила картинок — в [`../09-content.md`](../09-content.md), форматы — в
[`../04-data-model.md`](../04-data-model.md), раздача — в [`../03-server-api.md`](../03-server-api.md);
спецификация на них ссылается.

## Образец

```markdown
# Название

**Версия:** 1.1.0 **Состояние:** задумано | делается | сделано

## Зачем            — какую проблему игрока решаем, одним абзацем
## Что увидит игрок — экраны и поведение словами, без кода
## Данные           — файлы и ключи хранилища, только новые
## Протокол         — новые файлы на сервере в формате 03-server-api.md
## Неудачные случаи — что происходит, когда что-то пошло не так
## Критерии приёмки — список проверяемых утверждений
## Чего здесь нет   — явно отложенное, чтобы не обсуждать дважды
## Что изменилось по ходу работы
```

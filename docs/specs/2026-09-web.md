# Веб-версия: закрытая проверка с компьютера

**Версия:** 0.0.5 — закрытая; открытая — задумано, не раньше 0.2 **Состояние:** закрытая — сделано (работает с 29.09.2026)

## Зачем

Владелец хочет вышивать с компьютера: большие картины (четыре клетки на сантиметр холста,
до 852 × 556 клеток) удобнее вышивать на большом экране, а их проверка на телефоне идёт
медленно. Веб-сборка уже есть — на ней гоняется сценарий Playwright
([`../06-testing.md`](../06-testing.md), §5); её можно выложить на сайт студии.

Решение владельца от 28.09.2026: **сначала закрытая** — только для владельца, все картинки
сборки, включая музейные «только для проверки», по адресу `gornitsa.games/uzory/test/`
под паролем, который владелец задаёт на сервере сам. Открытая — позже, вместе с библиотекой.

## Что увидит игрок

Игрок — пока только владелец.

- Адрес <https://gornitsa.games/uzory/test/>: браузер спрашивает имя и пароль.
- Та же сборка, что APK 0.0.x: главная, «Лист», «Замер», «Файл работы». Экраны — колонкой
  шириной с планшет (640 точек); канва вышивания — во всю ширину окна, до 1600 точек;
  «Лист» на широком окне — сеткой, до четырёх карточек в ряд. Полосу нитей колёсико
  листает вбок.
- **Управление.** Левая кнопка мыши — как палец: щелчок — стежок, протянуть — кисть,
  двойной щелчок — заливка области, долгое нажатие — выбрать нить клетки. Колёсико —
  ближе и дальше вокруг курсора; щипок на тачпаде — так же. Правая или средняя кнопка —
  двигать канву. Клавиши: стрелки — сдвиг на пятую часть окна, «+» и «−» — масштаб,
  «0» — весь узор. Меню браузера по правой кнопке на канве не открывается. Сенсорный
  экран ноутбука — как телефон.
- При открытии картинки внизу канвы — строка «Колёсико — ближе и дальше, правая кнопка —
  двигать канву, двойной щелчок — залить область»; она не мешает щёлкать по клеткам под
  ней и уходит с первым стежком.
- **«Лист»**: начатая и не законченная картинка открывается с того же места, на карточке —
  «Вышито N % — откроется с того же места»; законченная — заново. Так же и в APK: большие
  картины за один раз не вышиваются.
- **«Свой узор»** (с 0.1.0, [спецификация](2026-09-custom.md)): снимок с компьютера →
  рамка кадра (мышью, колёсико — ближе и дальше) → размер и нити → узор с приговором
  «подходит» или «не подходит» → «Вышивать». Снимок остаётся в браузере; для владельца —
  «Карточка для библиотеки».
- Работы хранятся **в этом браузере**: на другом компьютере, в другом браузере и в APK
  их нет; «Очистить данные сайта» стирает их. Перенос работ файлом — в 0.2
  ([`2026-09-library.md`](2026-09-library.md)).

## Данные

- IndexedDB `uzory`, хранилище `files`: ключ — имя файла (`index.json`, `<работа>.log`
  и копии `.bak`, свои узоры — `mine.json` и `mine-<id>.json`), значение — байты в том же формате, что на телефоне
  ([`../04-data-model.md`](../04-data-model.md), «Файл стежков»). Прошлая версия и новая
  пишутся одной транзакцией. localStorage для работ не годится: около 5 МБ на сайт и только
  строки, а работа картины 852 × 556 — 600 КБ (в base64 — 800).
- Настройки и журнал сбоев — как раньше, в localStorage (AsyncStorage).

## Сборка и выкладка

- **Сборка для папки сайта:** `UZORY_WEB_BASE=/uzory/test npx expo export --platform web
  --output-dir dist-site`. `app.config.js` ставит `experiments.baseUrl`, Expo подставляет
  папку в адреса скрипта, шрифтов и `canvaskit.wasm` (`index.web.ts`). Без переменной
  сборка — как раньше, от корня.
- **CI** (`android.yml`, на тег версии): задание «Веб-сборка и сценарий» собирает
  и сборку для папки и проходит по ней тот же сценарий из папки `/uzory/test/`. Веб-версию для
  сайта собирает `site.yml` — раз в сутки, если `main` ушёл вперёд от выложенного, и вручную
  (устав, ADR 0019: слияние сборку не запускает). Он проходит тот же сценарий по сборке `main`
  для папки, шифрует её открытым ключом сервера сайта
  (age, <https://gornitsa.games/.well-known/uzory-age.pub>) и пишет ветку **`vps`**: один
  коммит без истории — `test.tar.gz.age` и `build.json` (коммит `main`, версия, время). Ветку
  пишет только CI и каждый раз затирает. Ключа на сайте ещё нет — предупреждение в итогах
  запуска и ничего не выкладывается.
- **Зачем шифровать.** Репозиторий открытый, а в сборке — картинки «только для проверки»,
  среди них картины российских музеев (ADR [0006](../adr/0006-content-sources.md)). Прочитать
  ветку может только сервер сайта: закрытый ключ (`/etc/uzory/age.key`) не покидает машину —
  так же «Вотчина» передаёт выгрузку базы.
- **Сервер** (репозиторий сайта `Nefeste/gornitsagames`, `deploy/uzory/`): таймер
  `uzory-pull` раз в 5 минут смотрит ветку `vps` (репозиторий открытый — ключ доступа
  не нужен; когда его закроют по ADR 0017 устава, серверу понадобится токен на чтение),
  новую сборку расшифровывает в `/opt/uzory/releases/<коммит>/test`, делает сжатые копии `.gz`
  и переключает ссылку `current`; хранит три последние. nginx отдаёт
  `/uzory/test/` из `current/test/` только по HTTPS и только с именем и паролем
  из `/etc/uzory/test.htpasswd`.
- **Пароль** владелец задаёт на сервере командой `sudo uzory-password` — имя и пароль
  вводятся там же, в терминале; ассистент пароль не видит и не хранит (устав студии).
- **Правила безопасности (CSP)** папки — как у сайта, плюс `'wasm-unsafe-eval'` (CanvasKit —
  это WebAssembly) и `blob:` для картинок. Сценарий Playwright отдаёт сборку с теми же
  правилами: что им не подходит, падает ошибкой в консоли. Поисковикам — `noindex`.
- **Что уже открыто.** Те же картинки лежат открыто в APK 0.0.x в Releases и исходниками
  в `content/` — это сборки и файлы для проверки, не выпуск для игроков. Открытая веб-версия —
  уже выпуск: картинки «только для проверки» в неё не идут.

## Неудачные случаи

- Файла паролей нет — `403` всем: страница закрыта, пока владелец не задал пароль.
- Сборка не расшифровалась ключом сервера (ключ сменился после переустановки) или в ней нет
  `index.html`, `canvaskit.wasm`, `build.json` — сервер пропускает её, остаётся прежняя;
  в журнале `uzory-pull` — строка об этом. Следующее слияние зашифрует новым ключом.
- CI не достучался до ключа на сайте — предупреждение в итогах запуска; выложит следующий
  запуск на `main` (или «Run workflow» на `main`).
- Браузер без WebGL или WebAssembly — CanvasKit не загрузится, экран останется пустым.
  Для проверки — Chrome, Яндекс Браузер, Edge или Firefox последних версий.
- Браузер не дал места — строка «Не удалось сохранить работу: браузер не дал места»,
  стежки держатся в памяти, запись повторяется через 10 секунд (как на телефоне).
- Одна работа открыта в двух вкладках — побеждает последняя записанная; не защищаемся:
  для одного проверяющего это не нужно.

## Критерии приёмки

- `npm run e2e` на сборке от корня и на сборке для папки (`E2E_DIST=dist-site
  E2E_BASE=/uzory/test`) — всё «да», без ошибок в консоли при правилах CSP сайта.
- В сценарии: колёсико приближает к курсору, правая кнопка двигает канву, «+» приближает,
  «0» возвращает весь узор — щелчок после каждого действия попадает в рассчитанную клетку.
- Начатая из «Листа» картинка открывается с тем же процентом.
- После запуска `site.yml` в ветке `vps` — `test.tar.gz.age` и `build.json` с коммитом `main`;
  без ключа сервера `test.tar.gz.age` не читается.
- На сервере: без файла паролей — `403`; с ним — `401` без пароля и `200` с паролем;
  `http://` переадресуется на `https://`.

## Чего здесь нет

- **Открытая веб-версия** — без пароля, только картинки с «да» владельца и решёнными
  правами (без `trial`), без подписки и покупок: RuStore Pay в браузере нет, а продавать
  мимо него нельзя ([`../10-money.md`](../10-money.md)). Нужна своя спецификация к 0.2;
  вопрос — в [`../07-roadmap.md`](../07-roadmap.md).
- Одни и те же работы в браузере и на телефоне.
- Установка на компьютер (PWA) и работа браузерной версии без сети.
- Раскладка главной и прочих экранов для широкого окна: колонкой, как на планшете;
  шире — только канва и «Лист» (сетка до четырёх карточек в ряд).
